# Portfolio Project - Claude Context

## Project Overview
PDF-like resume portfolio **template** with interactive project showcases. Built with Next.js 16, React 19, TypeScript, Tailwind CSS v4 and shadcn/ui. Data-driven via JSON with Zod schema validation.

## Tech Stack
- **Package Manager**: Bun
- **Framework**: Next.js 16 (App Router, static export)
- **Styling**: Tailwind CSS v4, shadcn/ui (New York) for interactive components (exception: list rows are native `<details>`)
- **Font**: Onest (one family, 15px base)
- **Icons**: Lucide React (lightbox/slideshow only)
- **Theme**: next-themes (system default, toggle available)
- **Validation**: Zod v4 (build-time JSON validation)

## Data Loading System

### JSON-Based Configuration
Resume data is loaded from JSON at build time with validation:

1. **Data Source Priority**:
   - If `RESUME_DATA_URL` env variable is set → fetch from URL
   - Otherwise → use local `lib/data/resume.json`

2. **Validation**: Zod validates data against schema at build time
3. **Version Check**: Major version must match `RESUME_SCHEMA_VERSION`

### Environment Variables
```bash
# Optional: Fetch resume JSON from external URL
RESUME_DATA_URL=https://example.com/resume.json
```

### Data Loader Usage
```typescript
import { getResumeData } from "@/lib/loader";

// In async server components
const resumeData = await getResumeData();
```

## Type System

Types are defined as Zod schemas in `lib/types/resume.ts`:

```typescript
// Schemas define validation rules
export const ResumeSchema = z.object({
  version: z.string(),
  name: z.string(),
  // ...
});

// Types are inferred from schemas
export type Resume = z.infer<typeof ResumeSchema>;
```

### Key Types
- `Resume` - Root type with version, name, meta, contact, sections
- `Section` - Contains id, title, limit?, items[]
- `SectionEntry` - Discriminated union (type: "timeline" | "list" | "showcase")
- `TimelineEntry` - For experience, education, certifications
- `ListEntry` - For skills
- `ShowcaseEntry` - For projects

### ShowcaseEntry Fields
- `slug`, `title`, `subtitle`, `link`, `description` - required; `link` (and timeline `link`) must be an absolute http(s) URL, shown as host/path
- `images` - required, non-empty array of `{ url, title? }` (slideshow when multiple). A YouTube URL renders its thumbnail with a play badge and embeds the player in the lightbox
- `status` - optional: "active" | "archived" | "development" (only non-active is shown)
- `featured` - optional boolean (not rendered)
- `links` - optional array of `{ type: "github"|"demo"|"website"|"docs", url }`

### SiteMeta Fields
- `keywords` - required string array (SEO keywords)
- `counter` - optional boolean (enables visitor counter in footer)

## Schema Generation

JSON schema is auto-generated from Zod types:

```bash
bun run generate:schema  # Generates public/resume.schema.json
```

Regenerated by `prebuild`, and formatted with Biome so the output stays stable.

## Features

### Intro
- If the first section holds only `summary` items it renders as the intro under the header, without a heading; the contact sentence follows it (or sits under the header when there is no intro)
- Summary content uses `<p>` paragraphs (16px apart), not `<br/><br/>`

### Section Limiting & View All
- Sections can have a `limit` field to show only N items on home page
- When limited, a "See all N" link (underline style) appears at section bottom
- Links to `/section/[id]`: breadcrumb header with count, the same rows without the limit, "Also see" other section pages
- **Only sections with `limit` get dedicated pages** - sections without `limit` don't generate `/section/[id]` routes

### Project Showcase
- **Thumbnail**: inside the opened row; 16:9, grayscale, rounded corners
- **Slideshow**: Embla Autoplay every 3s, stops on hover/focus, off under reduced motion; dots and ←/→ switch by hand
- **Lightbox**: shadcn Dialog (focus trap, Esc, focus return) + Carousel (swipe, ←/→); Home/End; click outside closes
- **Hover**: zooms 1.02 inside its frame and turns colour; no overlay
- **Video**: A YouTube URL in `images[]` shows its thumbnail with a persistent play badge (no expand icon) and embeds the player in the lightbox

## Design Rules ("quiet index", after paco.me / emilkowal.ski)
- **Colour**: grayscale only; ink, muted, faint tokens in `globals.css`; no accent
- **Layout**: one left-aligned 600px column, no navbar, footer pinned to the bottom on short pages (`min-h-dvh` + `grow`); vertical rhythm phones → md+: top 64 → 120, between sections 64 → 96, footer 80 → 120
- **Targets**: Button `size="text"` carries an invisible ::after hit area (≥24px, WCAG 2.5.8); prose links are exempt
- **Typography**: one size (15px) for everything except the footer (13px); headings are medium weight, sentence case
- **Lists**: name over grey subtitle, meta right-aligned; an openable row underlines its name and darkens its plus on hover/focus (`.row`)
- **Links/text buttons**: `<Button variant="quiet"|"underline" size="text">` (`asChild` around `<a>`/`<Link>`/`ExternalLink`); about-prose links styled via `.summary a`
- **Motion**: one load stagger (`.enter`, `--i`; first-screen blocks only, keyframes `rise-in` since tw-animate-css owns `enter`), opened row panels fade in (`details[open] > .panel-in`, never height), Button press scale .97; all off under reduced motion
- **No shadows**: flat design
- **Images**: grayscale, rounded-md, aspect-video

## Accessibility & SEO
- Rows are native `<details><summary><h2|h3>` (`components/resume/disclosure.tsx`): no JS, Enter/Space toggle, closed text stays in the HTML for crawlers, and the browser opens a row when find-in-page or a text fragment matches inside it. Radix Accordion can't do that (and React can't SSR `hidden="until-found"`), so rows don't use shadcn
- Row headings sit one level under the page: `h3` under a section `h2` on home, `h2` under the `h1` on section pages (`Section level`)
- External links go through `ExternalLink` (announces the new tab)
- Text colours meet WCAG AA; `--faint` is for decorative marks only
- JSON-LD: ProfilePage + Person, projects as `hasPart` CreativeWork (`lib/seo/structured-data.ts`)

## Code Conventions
- Server components by default, "use client" only when needed
- Data-driven rendering via `getResumeData()` async loader
- Entry-level type discrimination (`entry.type` determines rendering)
- shadcn/ui first: if shadcn has the component, use it (customise in `components/ui/*`, documented inline); plain elements only where none exists, or where the platform element does the job without workarounds (rows)
- Root fixes only: change the shared component, schema or sanitizer instead of overriding at the call site or patching the DOM
- Use `cn()` utility for conditional class merging

## Page Layout Conventions
- All pages render inside `DocumentContainer` (from root layout)
- **Home page**: No BackButton, starts with ContactHeader
- **Section pages**: breadcrumb header (`name / <h1>Section</h1>` + item count), rows, then "Also see" links to the other section pages
- **Other sub-pages** (404, error): start with `<BackButton />` (client; owner name from `OwnerProvider` in the layout)

## Build & Deploy
```bash
bun dev      # Development
bun build    # Schema generation + static export to out/
```
Configured for GitHub Pages deployment (output: "export").

## Template Usage

To use this as a template:

1. Fork/clone the repository
2. Edit `lib/data/resume.json` with your data (use `public/resume.schema.json` for validation)
3. Or set `RESUME_DATA_URL` to point to your hosted JSON file
4. Run `bun build` to generate static site

## Important
- **Keep CLAUDE.md updated** when making structural changes
- Always use Bun (not npm/yarn)
- Keep it quiet: no new colours, sizes or motion beyond the design rules
- Showcase image features (lightbox, slideshow) are intentional enhancements
- Zod is a dev dependency - only used at build time, not in static output
